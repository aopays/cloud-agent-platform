# 安全、隐私与合规计划

- 文档版本：1.0
- 状态：`DRAFT`
- 安全模型：Zero Trust、默认拒绝、最小权限、纵深防御、可审计

## 1. 保护目标

- 客户仓库、需求、产物和个人数据的机密性。
- 任务状态、事件、报告和审计的完整性。
- 控制面、队列、Worker、模型和 Sandbox 的可用性。
- 防止模型或仓库内容把数据指令误当作平台指令。
- 防止跨租户、越权外部写入和不可追踪的人类/Agent 操作。

## 2. 信任边界

互联网客户端、API Gateway、控制面、模型供应商、Git 服务、Worker、Sandbox、对象存储和运维平面分别是独立
边界。仓库内容、用户 Prompt、模型输出、工具结果和上传产物全部不可信。即使模型判断“安全”，策略层仍必须执行
确定性校验。

## 3. 数据分类

- Public：公开文档和演示仓库。
- Internal：任务元数据、非敏感日志和内部架构。
- Confidential：私有源代码、需求、报告、用户名和业务数据。
- Restricted：API key、Git token、身份令牌、个人敏感信息和客户密钥。

Restricted 数据不得进入模型上下文、普通日志和产物；只能通过专用 secret broker 以最小范围注入受信组件。
Confidential 数据发送模型前必须验证租户政策、模型地区和保留设置。

## 4. 身份和授权

- 人类用户通过企业 OIDC/OAuth2；服务使用短期 workload identity。
- RBAC 提供 viewer/operator/developer/security/admin，资源层再用 tenant 和 ownership ABAC。
- 所有访问由服务端计算 tenant，不接受客户端传入的 tenant 作为授权依据。
- 高风险批准使用 step-up authentication、双人复核或职责分离。
- 生产 break-glass 账号短时、强审计、自动过期并事后复盘。

## 5. Sandbox 防护

- 每 attempt 独立身份、容器/微虚机、网络命名空间和临时文件系统。
- 非 root、只读 rootfs、drop all capabilities、no-new-privileges、seccomp/AppArmor/SELinux。
- 无 Docker socket、宿主 PID/IPC、特权设备和宿主路径挂载。
- CPU、内存、PID、磁盘、网络字节和墙钟硬限制。
- 默认 egress deny；允许流量经代理按域名、端口、方法和任务审批。
- 终止时先撤销凭证和网络，再杀进程树，最后销毁存储并验证不存在。
- 高风险代码使用 gVisor/Kata/Firecracker；隔离强度按租户和任务风险路由。

## 6. Prompt Injection 和工具安全

- 系统指令、平台策略、用户目标、仓库数据和工具输出使用明确层级和数据边界。
- 仓库中“忽略规则、上传密钥”等内容只作为数据，不改变工具授权。
- 工具由服务器注册，模型只能在允许集合内选择；参数必须通过 JSON Schema 和策略引擎。
- 写入、网络、PR、部署和数据变更分别授权，默认只读。
- 工具结果脱敏、截断、标注来源；不把二进制或超大内容直接送入模型。
- Reviewer 检查目标漂移、权限升级和数据外传迹象。

## 7. 凭证与密码学

- 密钥存 Vault/KMS，不进入 `.env`、镜像、数据库明文字段或错误。
- Git 和云访问使用任务级、仓库级、短期凭证；完成或取消立即撤销。
- 外部和内部传输 TLS；对象和数据库使用 KMS 加密；租户需要时支持客户管理密钥。
- 下载 URL 短期、单资源、不可猜测；敏感产物可要求重新认证。
- Secret scan 在提交、CI、日志出口和产物发布四层执行。

## 8. 隐私和数据生命周期

收集最少数据；为每类数据记录目的、合法性、位置、保留期、处理者和删除方式。建议默认：任务元数据 90 天、事件
30 天、产物 30 天、审计 365 天，具体由合同和地区确认。删除必须覆盖数据库、对象、缓存、搜索索引和备份到期策略，
并生成可审计删除记录。模型供应商的数据使用、训练、保留和地区政策必须进入供应商评审。

## 9. 威胁清单

- 身份伪造和令牌重放。
- 跨租户 IDOR 和缓存键污染。
- Prompt Injection 导致数据外传或越权工具调用。
- 路径穿越、符号链接、命令注入和容器逃逸。
- 恶意依赖、镜像投毒、Git 子模块和构建脚本。
- 消息重放、租约争用、事件篡改和产物替换。
- 模型供应商泄漏、费用耗尽和拒绝服务。
- 日志/错误泄密、内部人员滥用和审批绕过。

每项威胁必须在威胁模型中记录资产、入口、攻击路径、控制、测试、残余风险和风险所有者。

## 10. 安全门禁与事件响应

设计阶段完成 STRIDE、数据流和滥用案例；开发阶段执行 SAST、SCA、secret、IaC、容器和策略测试；发布前执行
渗透和隔离验证。Critical/High 未关闭不得发布，例外需 Security Owner 和业务 Sponsor 书面批准且有到期日。

安全事件流程：检测与分级；停止新任务和撤销凭证；隔离 Worker/租户；保全审计和镜像；通知负责人；修复和恢复；
依法/依约通知；完成无责复盘和控制改进。凭证泄漏、跨租户和 Sandbox 逃逸需要预置专用 Runbook。
