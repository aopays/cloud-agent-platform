# Cloud Agent Platform 需求基线

> 扩展能力：在仓库执行任务之前，平台支持多轮需求发现会话。用户可以提交模糊需求和前置条件，
> FDE 通过分阶段澄清形成客户需求证据、已确认事实、默认假设、决策、风险和待确认项，
> 再生成可供架构、开发、QA、安全和客户共同评审的技术方案。
> 详细契约见 `docs/requirement-discovery.md`。

## 1. 产品定义

用户提交自然语言任务和代码仓库，平台创建一个隔离运行实例。自主 Agent 在预算和策略约束下调用 LLM 与工具，迭代执行直到完成、失败、取消或超时，最后返回状态、过程事件、产物和结果。

示例任务：读取指定仓库，找出所有 TODO，并生成报告。

## 2. 当前假设

以下信息尚未由真实业务方确认，实现前需要人工审阅：

- 假设核心目标用户是 FDE、解决方案架构师、AI 应用工程师、企业研发团队和内部开发者。
- 假设第一版是单区域、多租户 MVP，不承诺生产级 SLA。
- 假设输入以 Git 仓库 URL 和自然语言任务为主。
- 假设 P0 主要执行只读代码分析，但底层工具接口预留受控写文件能力。
- 假设单任务最长 15 分钟、最多 30 个 Agent 轮次。
- 假设默认禁止公网访问；拉取仓库由受控准备阶段完成。
- 假设第一版不自动创建 PR、不部署用户代码、不访问企业数据库。
- 假设用户可以查看任务状态、事件和最终产物。

## 3. P0 范围

- FDE 客户发现：围绕业务结果、现状证据、责任人、范围、数据集成、安全和验收进行多轮访谈，输出技术方案草案。
- 创建任务：自然语言目标、仓库 URL、可选分支或提交哈希。
- 查询任务：当前状态、开始/结束时间、失败原因和资源使用摘要。
- 取消任务：向运行中的 Worker 和沙箱传播取消信号。
- 准备仓库：在独立工作目录中拉取或复制代码。
- Agent Loop：LLM 推理、结构化工具调用、观察结果、继续或终止。
- 基础工具：列目录、读文件、搜索文本、受控执行命令、提交结果。
- 预算控制：总时间、轮次、token、单命令时间和工具输出大小。
- 沙箱：每任务隔离、非 root、资源限制、默认禁网、完成后销毁。
- 事件记录：状态变化、公开行动摘要、工具调用、结果摘要和错误。
- 产物：至少支持文本报告和可下载文件。
- 最小可观测性：结构化日志、任务 ID、attempt ID、耗时和 token 使用。

## 4. P1 范围

- 私有仓库凭证的临时注入和审计。
- SSE 实时事件流和更完整的 Web UI。
- 模型路由、限流、配额和费用统计。
- 高风险工具调用的人工审批。
- 基础设施故障重试和 Worker 租约恢复。
- S3 兼容对象存储。
- 生成代码补丁，但不自动写回远程仓库。

## 5. P2 范围

- Kubernetes Job、gVisor、Kata 或 Firecracker 隔离。
- 预热沙箱池和多资源规格调度。
- 多 Agent 协作、断点恢复和运行回放。
- 工具插件市场、企业 RBAC、多地域与正式 SLA。
- 自动创建 commit、PR 或部署，需要独立审批策略。

## 6. 非目标

- 第一版不复刻完整 Devin 或 Claude Code Cloud。
- 不允许用户代码直接访问宿主机。
- 不以 Docker 容器等同于处理完全不可信代码的最终安全边界。
- 不记录或展示模型私有思维链。
- 不在未授权情况下产生外部写入或付费操作。

## 7. 核心用户流程

1. 用户提交任务和仓库信息。
2. API 验证请求并创建任务记录。
3. 调度器投递任务，Worker 获取执行租约。
4. Worker 准备代码和隔离沙箱。
5. Agent Runtime 调用模型并执行经策略校验的工具。
6. 平台持续写入事件、预算和资源使用信息。
7. Agent 提交结果，或任务进入失败、取消、超时状态。
8. 平台收集产物并销毁沙箱。
9. 用户查询最终结果和执行摘要。

## 8. 需要业务方确认的问题

- 是否必须支持私有 Git 仓库？使用哪种凭证方式？
- P0 是否允许修改工作区文件，还是严格只读？
- 是否允许安装依赖？允许访问哪些包源？
- 是否需要 Web UI，还是 API/CLI 演示即可？
- 目标并发量、任务时长和费用上限是什么？
- 是否存在数据地域、保留期限或合规要求？
- 任务产物是否需要长期保存？
- 哪些工具调用必须人工审批？
