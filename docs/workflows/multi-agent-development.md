# 多 Agent 并行开发工作流

## 1. 团队拓扑

默认使用 1 个主 Agent 和最多 3 个并行子 Agent：

```text
Tech Lead / Integrator
  |- Backend & Scheduler
  |- Agent Runtime & LLM
  `- Sandbox & Security
```

第二轮复用并发名额执行 QA、安全和可靠性审查。

## 2. Gate 0：需求冻结

输入：模糊业务需求和沟通记录。

必须完成：

- P0、P1、非目标和假设。
- 核心用户流程与异常流程。
- API、事件和状态机契约。
- 安全边界和审批边界。
- 可执行验收标准。

退出条件：没有会显著改变架构或数据模型的未决问题。

## 3. Gate 1：公共骨架

此阶段由主 Agent 串行完成：

- 初始化项目和依赖。
- 创建公共接口、Schema 和 stub。
- 创建数据库迁移和容器编排。
- 确定测试与启动命令。
- 将任务看板中的第一波任务标记为 `READY`。

退出条件：三个专业任务不需要修改共享文件即可实现。

## 4. Wave 1：并行开发

主 Agent 同时派发三个任务，并为每个任务指定不重叠的代码所有权。

子 Agent 开始时：

1. 阅读任务单和必读文档。
2. 检查已有变更。
3. 验证输入接口存在。
4. 仅在授权目录工作。

子 Agent 结束时：

1. 运行相关验证。
2. 检查修改文件范围。
3. 按统一格式返回报告。
4. 不创建 commit，不修改任务看板。

## 5. Gate 2：主 Agent 集成

主 Agent 按以下顺序集成：

1. 审查每个子 Agent 的修改和证据。
2. 处理共享依赖和公共接口。
3. 运行模块测试。
4. 运行跨模块集成测试。
5. 运行成功、取消、超时和策略拒绝的端到端测试。
6. 更新任务看板状态。

如果出现失败，优先定位责任模块。只有修改范围独立时才重新并行分发。

## 6. Wave 2：并行独立审查

审查 Agent 默认只读：

- QA：需求覆盖、测试质量、异常流程和可复现性。
- Security：路径、容器、资源、网络、凭证、注入和清理。
- Reliability：幂等、重试、租约、取消、并发和终态一致性。

所有发现必须有证据。主 Agent负责验证、去重和排序。

## 7. Gate 3：修复和回归

- Critical、High 优先。
- 修复任务重新声明所有权。
- 对每个问题运行最小回归。
- 最后运行完整测试套件。
- 更新 README、已知限制和演示步骤。

## 8. 何时停止并行

出现以下情况时改为串行：

- 两个任务必须频繁修改同一文件。
- 公共契约仍在变化。
- 根因未知，需要统一诊断。
- 子任务预计几分钟即可完成，协调成本更高。
- 正在进行最终集成、迁移或发布判断。

## 9. 进度汇报提示词

运行过程中可向主 Agent发送：

```text
请汇报当前主任务和每个子 Agent 的状态、已完成内容、正在执行内容、阻塞项和下一检查点。不要停止仍在安全执行的任务，不要重复已完成工作。
```

方向调整时使用：

```text
新增或变化的要求是：<要求>。
先分析影响模块和依赖，更新任务看板；只向受影响的 Agent 发送增量任务，不要重新启动或覆盖已完成工作。
```
